# T-026BK — Relax the research quality gate prompt (redirect URLs + no contacts)

**Date:** 2026-06-01
**Status:** Accepted, implemented
**Scope:** `apps/agent` gate instruction (prompt only). Agent rebuild.

## Problem

Even after T-026BJ restored evidence URLs, snapshots stayed `draft` and no
drafts generated. Traced the gate: `runResearchQualityGate` runs correctly,
parses the verdict, and would promote — but the gate agent always returns
`sufficient: false`. Inspected the decisions for Bode (every retry, retry
0–2): reasons were consistently

- "Many facts lack verified source URLs" / "evidence URLs are redirect URLs",
- "No contact candidates found (count 0)", "No LinkedIn / emails".

Both are unsatisfiable by design:

1. Vertex `google_search` returns sources ONLY as grounding-redirect URLs.
   The gate prompt explicitly said "evidence URLs should be primary, NOT
   Vertex redirect URLs" — so it penalized the only URL form Vertex ever
   produces. Directly contradicts T-026BJ (which keeps redirects as valid).
2. The gate asked for "enough contact/signal details", but contacts are found
   by a SEPARATE contact-discovery stage AFTER the gate. At gate time the
   snapshot has zero contacts by design, so the gate could never be
   satisfied.

Net effect: `sufficient` was practically unreachable → snapshots never
published → auto-draft never fired for gate-flagged orgs.

## Fix (prompt only)

Edit `_RESEARCH_QUALITY_GATE_INSTRUCTION`:

- Scope the gate to COMPANY FACTS only. Explicitly: contacts are out of
  scope, never require emails/LinkedIn, never list their absence as a reason
  or missing item.
- Declare grounding-redirect URLs a VALID source; only a null/empty URL on an
  otherwise-useful fact is a weakness.
- Rules: `sufficient=true` when there are concrete evidence-backed company
  facts and a clear identity; contact availability is not a criterion;
  follow-up queries are about the company, not contacts.

No code/schema change — the decision shape and the wiring
(gate → promote → auto-draft) are already correct (verified while debugging).

## Verify

Live: refresh a previously-stuck org (Bode). The gate should now return
`sufficient: true` → `promoteSnapshotOnQualityPass` flips the snapshot to
`published` → `maybeAutoGenerateDraft` enqueues a draft. Confirm the
research_quality_gate_completed event shows sufficient=true and the org gets
a draft.

## Build

`apps/agent` prompt change → `docker compose build agent` + recreate. No db
change.
