# T-026BI — Auto-generate cold drafts for verified, addressable orgs

**Date:** 2026-06-01
**Status:** Design accepted, ready for implementation
**Scope:** `packages/db` (auto-gen + org read) + `apps/dashboard` (org draft
panel, draft-page email edit, manual-draft drawer). Worker rebuild.

## Problem

Discovery → research → contacts run automatically, but draft generation is
manual: the operator opens each organization and clicks "Generate AI draft".
For a 10-org campaign with 22 addressable contacts that is 10 manual clicks.
The operator wants drafts to appear on their own once an org is ready, shown
on the org page with read / send / discard / regenerate / edit actions.

## Goal

When an org becomes draft-ready, auto-enqueue one cold draft for it. The
draft is only generated — approval and send stay manual (zero-autosend
invariant #58/#59 preserved). The org page surfaces the draft (subject,
recipient, body excerpt, status) with actions. Plus two adjacent UX fixes:
edit the contact email from the draft page, and move the manual "create
draft" form into a drawer.

## Draft-ready condition (all required)

1. Org has a **published** research snapshot (passed the quality gate,
   T-026BG).
2. Org has at least one **addressable** contact (email present).
3. The published snapshot has **active facts**.
4. Source campaign is **active**.
5. No existing draft for the org (status draft/approved/sending/sent) —
   one draft per org (#8/#263).
6. Campaign open-draft-review count is below `maxOpenDraftReviews` (#252
   backpressure) — do not flood the review queue.

## Trigger placement

`maybeAutoGenerateDraft(organizationId, correlationId)` — a standalone async
helper that runs its own queries (NOT inside a router tx) and, if all
conditions hold, calls the existing `generateDraftCommand` (which resolves
the primary/fallback contact and opens its own tx). It runs at two job-
handler points, AFTER the relevant tx commits, so whichever finishes last
fires it:

- after `routeContactDiscoveryOutcome` (a contact was just created), in
  `completeDiscoverContactsJob`.
- after `promoteSnapshotOnQualityPass` flips a snapshot to published, in the
  refresh/research_more handlers.

Idempotency: condition #5 (no existing draft) + the existing
`concurrencyKey: generate_draft:<orgId>` guard prevent duplicates under
concurrent contact/snapshot events. `generateDraftCommand` is reused
verbatim — primary contact resolution, payload, job enqueue all unchanged.

## Decision-log #306 (new)

> Cold drafts auto-generate when an org has a published research snapshot, an
> addressable primary contact, active facts, in an active campaign, below the
> campaign's open-draft-review cap. Auto-generation produces a draft only;
> approval and send remain operator-initiated — the zero-autosend invariant
> (#58/#59) is preserved. One draft per org (#8/#263). The operator may
> open / edit / send / discard / regenerate from the org page. The manual
> generate-draft command remains as a fallback.

## Org draft panel (UI)

`getOrganizationDetail` += `latestDraft`:
```
latestDraft: {
  id, version, status, subject, bodyExcerpt (~300 chars),
  contactEmail, contactName, qualityScoreBand, autosendReadiness,
  sendable: boolean   // evaluatePreSendGuardrails passes + status=draft + email
} | null
```
`<OrgDraftPanel>` renders by status:
- none → "Draft will auto-generate once research is verified and a contact
  is found" + the manual generate form stays as fallback.
- draft → preview card (subject, to: name <email>, body excerpt, quality
  badge) + buttons: Open / Edit (→ /drafts/[id]), Send (if sendable),
  Discard, Regenerate.
- approved/sending/sent → "✓ Sent to <email>" + Open.
- send_failed_post_approve → "⚠ Send failed" + Open + Retry.

Actions reuse existing commands (POST /api/commands): Send →
`approve_draft_for_send` (+ guardrails, not bypassed), Discard →
`discard_draft`, Regenerate → `generate_draft`, Open/Edit → link.

## Draft-page email edit (UI)

Add a "Change contact email" form on /drafts/[id] near the recipient,
posting the existing `set_contact_email` command. Covers: auto-draft
generated but the contact email is wrong/missing → fix and send without
leaving the draft page. Changes the contact's email (draft picks it up via
contact_id).

## Manual-draft drawer (UI)

Move the `create_draft` form off the top of /drafts into a SideDrawer behind
a "Create manual draft" button. The listing stays clean; manual creation is
one click away. Reuses the existing SideDrawer component.

## Tests (`packages/db/test`)

`auto-draft-generation.test.ts`:
1. published snapshot + addressable + active facts + active campaign →
   enqueues one generate_cold_draft job.
2. draft already exists → no duplicate.
3. snapshot still draft (not published) → no draft.
4. no addressable contact → no draft.
5. campaign not active → no draft.
6. open-draft-review cap reached → no draft.

Extend the org-detail test for `latestDraft`.

## Build impact

`packages/db` change → rebuild worker + worker-telegram. Dashboard via hot-
reload. No migration.
