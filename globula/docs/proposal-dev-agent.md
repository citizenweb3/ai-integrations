# Globula — AI Dev Agent: Предложение

**Дата:** 2026-03-16
**Статус:** Ориентировочное предложение (до уточнения деталей)

---

## Что предлагаем

Автоматизация разработки через AI-агентов, которые берут задачи из GitHub Issues, пишут код, создают Pull Request, проводят автоматическое код-ревью и исправляют замечания. Человек проверяет и мёрджит готовый результат.

Это не абстрактная идея. Система уже разработана и протестирована на реальном проекте (ValidatorInfo, fullstack: Next.js + Prisma + PostgreSQL). Мы адаптируем её под стек Globula (Unity + backend).

---

## Как это работает

### Полный цикл задачи

1. **Человек создаёт Issue** в GitHub с описанием задачи и ставит лейбл (например `agent:backend` или `agent:gamedev`)
2. **GitHub Actions workflow** автоматически подхватывает Issue и направляет на нужный контейнер
3. **AI-агент** (Claude Code) читает описание задачи, изучает кодовую базу, реализует решение
4. **Агент создаёт Pull Request** с описанием что и почему было изменено
5. **Второй агент-ревьюер** автоматически проверяет PR: code quality, баги, безопасность, соответствие стилю проекта
6. **Если есть замечания** — агент автоматически исправляет и пушит (до 2 итераций)
7. **Человек получает готовый PR** с результатами ревью — проверяет и мёрджит

Весь процесс от Issue до готового PR: от 5 до 30 минут в зависимости от сложности задачи.

### Что умеет агент

- Фиксить баги по описанию (стектрейс, шаги воспроизведения)
- Реализовывать фичи по спецификации
- Рефакторить код
- Писать и обновлять тесты
- Работать с базой данных (миграции, запросы)
- Декомпозировать сложные задачи на подзадачи и выполнять параллельно (Agent Teams)

### Что НЕ делает агент

- Не мёрджит PR без одобрения человека
- Не деплоит на продакшен
- Не принимает архитектурных решений без согласования (создаёт Issue с предложением)
- Не имеет доступа к секретам и ключам (только к коду)

## Варианты

### Вариант A — Базовый: Code + Review

| Компонент | Что делает |
|-----------|-----------|
| **task-execute** workflow | Issue → агент пишет код → PR |
| **pr-review** workflow | Автоматическое код-ревью каждого PR |
| **1 agent persona** | Промпт под стек проекта (технологии, правила, стиль кода) |
| **Monitoring** | SQLite база: логи запусков, время выполнения, результаты |

**Что получает человек:** создаёт Issue → через 10-20 мин получает PR с результатами ревью → проверяет и мёрджит.

**Ограничения:** если ревьюер нашёл проблемы, человек должен либо сам поправить, либо написать комментарий и вручную запустить фикс.

---

### Вариант B — С автофиксом: Code + Review + Fix (рекомендуемый)

Всё из Варианта A, плюс:

| Компонент | Что делает |
|-----------|-----------|
| **pr-fix** workflow | Автоматически исправляет замечания ревьюера |
| **Цикл ревью** | Review → Fix → Re-review (до 2 итераций автоматически) |
| **Человеческий фикс** | Если человек запросил изменения в PR, агент тоже чинит (неограниченно) |

**Что получает человек:** создаёт Issue → через 15-30 мин получает PR, уже прошедший ревью и автофикс → проверяет и мёрджит.

**Почему рекомендуем:** ревьюер отсеивает 80% проблем до человека. Автофикс закрывает замечания без участия человека. Человек тратит время только на финальную проверку.

---

### Вариант C — Multi-agent: Agent Teams

Всё из Варианта B, плюс:

| Компонент | Что делает |
|-----------|-----------|
| **Agent Teams** | Лид-агент декомпозирует задачу, спавнит субагентов параллельно |
| **Несколько persona** | Отдельные промпты для backend, gamedev, devops |
| **Team workflow** | Plan → Implement (параллельно) → Review → PR |

**Что получает человек:** создаёт сложный Issue → лид-агент разбивает на подзадачи → субагенты выполняют параллельно → лид собирает, ревьюит, создаёт PR → человек мёрджит.

**Когда нужен:** крупные фичи, затрагивающие несколько модулей. Для типовых багфиксов Вариант B достаточен.

## Сравнение вариантов

| | A: Базовый | B: С автофиксом | C: Multi-agent |
|---|---|---|---|
| Issue → PR | + | + | + |
| Автоматическое ревью | + | + | + |
| Автофикс замечаний | — | + | + |
| Декомпозиция задач | — | — | + |
| Параллельное выполнение | — | — | + |
| Несколько ролей агентов | 1 | 1 | 2-3 |
| Сложность настройки | Низкая | Средняя | Высокая |
| Время на адаптацию | 2-3 дня | 3-5 дней | 1-2 недели |

## Инфраструктура

### Что нужно

| Компонент | Описание | Стоимость |
|-----------|----------|-----------|
| **Docker контейнер** | На сервере клиента (у вас свои серверы — идеально) | $0 |
| **Claude Max подписка** | 1 подписка на Anthropic (claude -p CLI) | ~$100/мес |
| **GitHub Actions** | Self-hosted runner в контейнере | $0 |
| **Мониторинг** | SQLite внутри контейнера | $0 |

**Итого инфраструктура:** ~$100/мес (только подписка Claude).

### Что уже готово (переиспользуем)

- Docker-образ с Claude CLI, GitHub Actions runner, инструментами
- 3 GitHub Actions workflow (task-execute, pr-review, pr-fix)
- 10 skills для агента (TDD, debugging, code review, verification и др.)
- Monitoring: SQLite схема, wrapper-скрипт для логирования
- Документация по настройке и troubleshooting

### Что адаптируем под Globula

- Agent persona: создаем специализированный промпт-файл с описанием стека (Unity, C#, ваш бекенд), правилами кодстайла проекта, архитектурными паттернами проекта
- GitHub labels и routing (какие лейблы → какой агент)
- CLAUDE.md: правила проекта, которые агент читает перед каждой задачей (аналог onboarding-документа для нового разработчика)

## Как выглядит работа после запуска

### День разработчика с агентом

```
09:00  Разработчик открывает GitHub, видит 3 бага от QA
09:05  Создаёт 3 Issues с лейблом agent:backend
09:06  Переключается на свою работу (дизайн новой фичи)
09:30  Приходят уведомления: 3 PR готовы, ревью пройдено
09:35  Открывает PR #1 — чистый фикс, 12 строк, тесты зелёные. Мёрджит.
09:37  PR #2 — агент исправил баг, но ревьюер попросил добавить edge case тест.
       Агент уже пофиксил и ревью прошло. Мёрджит.
09:40  PR #3 — сложный баг, агент нашёл root cause но предложил два варианта
       фикса в описании PR. Разработчик выбирает вариант, пишет комментарий
       "/fix используй вариант 2". Агент исправляет за 5 минут.
09:45  Все 3 бага закрыты. Разработчик продолжает свою работу.
```

### Мониторинг

```sql
-- Последние запуски агентов
SELECT agent, status, exit_code, duration_ms
FROM agent_runs ORDER BY started_at DESC LIMIT 10;

-- Статистика за неделю
SELECT agent, COUNT(*) as tasks, AVG(duration_ms) as avg_time,
       SUM(CASE WHEN status='success' THEN 1 ELSE 0 END) as success
FROM agent_runs WHERE started_at > date('now', '-7 days')
GROUP BY agent;
```

## Ограничения и честные ожидания

- **AI не заменяет сеньоров.** Он закрывает типовые задачи (баги, небольшие фичи, рефакторинг), освобождая время для архитектурных решений и сложной работы.
- **Качество зависит от описания задачи.** Чёткий Issue с контекстом → хороший PR. Расплывчатое "сделай лучше" → плохой результат.
- **Первые 1-2 недели — калибровка.** Агент учится на правилах проекта (CLAUDE.md). Промпт дорабатывается по мере реальных задач.

## Следующие шаги

1. Клиент заполняет опросный лист
2. Мы проводим аудит репозитория: стек, структура, тесты, CI/CD
3. Пишем agent persona и CLAUDE.md под проект
4. Настраиваем инфраструктуру (Docker + runner + secrets)
5. Тестируем на 5-10 реальных задачах, калибруем промпт
6. Передаём в работу
